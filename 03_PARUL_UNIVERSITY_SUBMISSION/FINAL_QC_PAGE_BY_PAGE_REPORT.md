## 4. LOCAL PERSISTENCE: ROOM SQLITE VS. FILESDIR STORAGE AUDIT

A critical technical verification was performed to distinguish between SQLite database usage and filesystem binary storage:

1. **Physical Codebase Inspection (`01_APP_ANDROID\android_project\app\`):**
   * **Room SQLite Dependencies:** **ABSENT**. `build.gradle.kts` does **not** include `androidx.room:room-runtime`, `androidx.room:room-compiler`, or `androidx.room:room-ktx`.
   * **Receipt Image Storage:** **PRESENT**. Handled by `com.example.liferece.util.LocalReceiptManager.kt` via standard Java I/O (`java.io.File`, `java.io.FileOutputStream`) writing directly to `context.filesDir/local_receipts/<id>.jpg`.
   * **Structured Data Persistence:** **PRESENT**. Handled by the **Google Cloud Firestore Android SDK's built-in offline disk persistence / local cache**, which caches `/transactions`, `/budgets`, and `/aiInsights` locally without requiring a separate Room SQLite layer.
2. **Web Persistence Inspection (`02_WEBSITE\src\`):**
   * Handled by `src/services/localReceiptStore.ts` using native browser `IndexedDB` (`drvlife_local_receipts`) for image Blobs, and Firebase JS SDK offline cache for metadata.
3. **Audit Finding:**
   * Text in `FINAL_MCA_PROJECT_REPORT_CORRECTED.docx` (P118, P209, Table 7.4), `DRVLIFE_MCA_PROJECT_PRESENTATION.pptx` (Slide 7), and `DRVLIFE_MCA_VIVA_PREPARATION.docx` (Q36, Q64–66, Q111–114) claims that an Android Room (SQLite) database is implemented.
   * **This is technically inaccurate.** The app utilizes `context.filesDir` for images and Firestore offline caching for data. Claiming Room in viva defense presents a technical discrepancy if an examiner requests Room DAO code.
